Boundary Lab usage guide

Boundary Lab is a local diagnostic surface for the native C++ pipeline. The browser prepares inputs and draws results; the discrete merger, fitter, optimizer, and filled-region reference renderer all run through the public C ABI.

Recommended raster workflow

  1. Open Raster image, choose one local image, and stay on Source to verify dimensions.
  2. Choose a requested region count, then run Discrete VBRM on the complete source raster.
  3. Inspect Flat regions first. It deliberately contains no borders. If a feature is absent here, curve fitting or Yang optimization cannot restore its topology.
  4. Use Boundaries to inspect the label interfaces and Region graph to find fragmentation or unexpected adjacency.
  5. Run Shared boundary fit. Inspect chain/cubic count and recovery status. A planar-guide recovery is a compact fit that retains RGB targets; it is different from exact-grid fallback.
  6. Compare Initial curves against target samples, then optimize. The default staged run applies the fast boundary/prior pass followed by sparse filled-RGB geometry and region-color refinement.
  7. Review Final SVG for vector quality and download that output. Use Optimized curves for geometry diagnostics, and Initial fill/Final fill for numeric raster comparisons. Those sampled fills are not the SVG preview.

Reading the controls

Every parameter has a ? button. Help explains its effect, relevant tradeoffs, constraints, and which stage to rerun. Controls with conditional or unavailable behavior say so. Press the same button to close it. Opening another tip closes the current one.

Advanced controls are intentionally collapsed. Start with region count, RMS allowance, boundary max step, and raster sweeps/samples. Open an advanced group when a report points to a specific limit, topology retry, convergence, or performance issue.

Defaults (Pipeline header) restores every optimizer, discrete, fit, filled-RGB refinement, and score control from the native C defaults plus the lab UI defaults. Toolbar Reset only restores the current geometry, not parameters.

Live rebuild (toolbar) re-runs the earliest affected pipeline stage 500 ms after each settled parameter or handle edit, then replays later stages that already had results—including filled-RGB refinement when enabled. Leave it off for large images or expensive sample counts.

Evidence weight and Targets / cubic sit under Boundary optimizer, but their data is prepared during fitting. After changing either, run Fit curves → Optimize. Initial curve geometry will be unchanged. Contrast floor stays with subpixel evidence because it affects both localization and optimizer target weights.

In curve previews, Label grid is the exact connected topology from the merged raster. Evidence path alternates shared refined vertices with every raw RGB edge observation, so it preserves source adjacency; it is diagnostic and is not yet optimizer quadrature. Target dots are the bounded optimizer observations and are not a path. Assignments draws each visible dot to its published point on the initializer; red dots/spokes flag clamped, non-increasing, invalid, or greater-than-one-pixel assignments. The diagnostics below the overlays report the complete fitted set even when drawing is capped.

Shared settings holds Threads and Preserve topology for fitting and both optimizers. Flatness and cell size affect only the two optimizers. Raster inputs need a refit when Preserve topology changes; Live rebuild now starts there.

Saliency weight and Topology weight are disabled: the browser does not supply the boundary-protection maps they require. They do not preserve image detail in this lab.

Normalization and units

Geometry always stays in source-pixel coordinates. Off, the tuned default, accumulates raw boundary data and raw APT/HPT/LPT priors. Yang divides only data by one fixed initial l0 for the complete shared network and leaves the priors raw. Scale-balanced restores the earlier per-chain data/length and segment/handle balancing.

Changing normalization changes the data/prior ratio. Retune Angle, Handle, and Length instead of carrying the same numbers across modes. The paper's weights were calibrated for its full raster objective; the lab defaults are calibrated for raw boundary-local evidence.

Discrete VBRM always receives the complete natural-size raster. The displayed solver scale is max(1, sqrt(W×H / 512²)) source pixels per reference pixel and is shared by fitting, boundary optimization, and raster optimization. Native code converts fit error, support windows, robust delta, max step, handle epsilon, topology tolerances, active margin, and dimensioned prior coefficients; it does not resize the raster or the curves. The RGB localization clamp remains at most ±0.5 actual source pixel.

This area-equivalent scale makes uniform resizes comparable. It cannot infer physical object scale across unrelated crops; use known acquisition/export scale in a production caller when available. The report displays the exact value used.

What the stages guarantee

The label map is authoritative topology. RGB subpixel evidence may move an existing interface but never add or delete one. Every shared interface is fitted once, so neighboring regions cannot receive independently drifting outlines. The initializer follows the active-contour distinction between a source contour and its Bézier approximation: it first tries RGB-refined guides, then switches only the guide to the planar label contour if necessary while keeping RGB optimization targets. With topology preservation enabled, Yang returns the last planar geometry and reports every rejected retry.

The filled reference renderer traverses the region pair on every curve crossing and rejects a network that cannot reproduce the supplied label topology. sRGB scoring matches Yang's image-space RGB formulation and the existing logo studies; Linear RGB is a separate physical-coverage diagnostic. Samples per axis trades quadratic residual cost for more accurate box coverage.

The sparse raster stage moves geometry with an analytic pixel-box coverage derivative, overlapping five-control/two-cubic systems, and joint APT/HPT/LPT acceptance. It alternates two exact-coverage sparse least-squares updates of Yang's region colors. Additive scheduling is the fast default; Ordered colors refreshes the residual and derivative between two or three non-conflicting batches as a bounded-cost approximation to Yang's multiplicative traversal. The remaining paper differences are the fixed-sample box renderer instead of hierarchical Haar coefficients and no literal rerender after every individual block.
